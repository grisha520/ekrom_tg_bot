## Что это
Telegram-бот подбора техники **ekrom.ru**. Клиент пишет запрос → бот подбирает по
каталогу → присылает PDF. Бот: **@ekroom_bot**. Прод на VPS.

## Стек
- Python 3.12 (сервер) / 3.13 (локально), пакет `max_ekrom_bot`, aiogram 3.20 (long polling).
- **YandexGPT** Lite (парсер) + Pro (резолвер категорий + attr-маппер). Playwright (ekrom).
- reportlab (PDF). SQLite (кэш каталога + история + метрики). ~191 тест pytest.
- Ядро `pipeline.py`: parse → резолвер → attr-mapper(схема) → кэш → селектор → enrich → PDF.

# АКТИВНАЯ ЗАДАЧА: «Комплекты 5 брендов по акциям»

**Суть (от заказчика):** переориентировать бота — работать **только с 5 брендами**
(Korting, Maunfeld, Midea, Lex, Kuppersberg), собирать **комплекты техники из ОДНОГО
бренда** на основе **раздела «Акции»**, учитывать **дизайн-совместимость**, и выдавать
**PDF, визуально идентичный** документу корзины ekrom (эталон прислан).

## Решения заказчика (приняты)
1. **Полная замена** — бот работает ТОЛЬКО с 5 брендами и комплектами (текущий подбор
   по всему каталогу отключается; инфраструктура переиспользуется с фильтром брендов).
2. **Данные — бот сам с сайта** (краул акций + характеристики; Excel НЕ дают).
3. **Итог акции считает бот** (кодируем механики кампаний).
4. **PDF — свой генератор** (reportlab), но **точь-в-точь как эталон** (НЕ брать cart_pdf.php).

## Разведка сайта (факты)
- **2053 товара** 5 брендов: korting 659, lex 554, maunfeld 526, kuppersberg 183, midea 131.
- **«Акции» = набор кампаний**, каждая — своя страница `/catalog/aktsii/<slug>/`; верхняя
  `/catalog/aktsii/` карточек товаров не содержит. Многие кампании комплектные:
  `korting_skidki_pri_pokupke_komplekta`, `kuppersberg_skidka_na_komplekt`,
  `kuppersberg_kaskadnaya_skidka`, `maunfeld_soberi_svoyu_skidku`, `..._v_podarok`.
  Механики РАЗНЫЕ: скидка на комплект / каскадная (чем больше позиций — тем больше %) /
  техника в подарок.
- **Дизайн-коллекция в данных почти отсутствует:** «Коллекция» лишь у 28 товаров, «Стиль»
  у 364. → совместимость по дизайну надёжно не вытащить; эвристика: **бренд + цвет/финиш +
  стиль/тип управления**. Честно предупредить, что это «визуально сочетается», не «одна линейка».
- **Эталонный PDF = документ корзины ekrom** (`cart_pdf.php`): шапка «Корзина от …»,
  карточки (фото+название+артикул+характеристики+цена, «Скидка −30%» + старая зачёркнута),
  блок «Итого» (Сумма без скидки / Индивидуальная скидка −X% / Сумма со скидкой), сервис-
  пункты, карточка менеджера (имя/почта/телефон), адреса шоурумов. Дамп текста:
  `scratchpad/ref_pdf_dump.txt` (если сохранился), сам файл был в Downloads/document (2).pdf.

## План по фазам (8–11 дней)
- **Ф1. Данные — СДЕЛАНА.** Краулер `ekrom/promos.py` (httpx, куки сессии) + хранилище
  `ekrom/promo_store.py` (таблицы `promo_campaigns`/`promo_items` в `catalog.db`) +
  `scripts/crawl_promos.py`. Тесты `tests/test_promos.py` (14). Датасет: **15 кампаний
  4 брендов, 147 витринных товаров.** По кампании: бренд, механика, срок, `scope`
  (all_brand/listed), `requires_oven`, текст правил, тарифная сетка `tiers` {кол-во→%},
  витринные участники (url/product_id/цена/старая цена).
  - **Механики (классификатор + сетки распознаются из текста правил):**
    `cascade_cheapest` — % на НАИМЕНЬШИЙ товар, растёт с числом позиций (Korting/Kuppersberg
    «Каскадная»/Midea: 2→25 3→50 4→75 5→100%); `flat_combo` — плоский % на весь комплект
    (Kuppersberg-комплект 2→5 3→7 4→10 5→12%; Maunfeld «Собери» 3→8 4→11 5→13 6→15%);
    `gift` (7 кампаний — техника/аксессуар в подарок); `spec_price`; `unknown` (правила
    баннером-картинкой без текста → итог уточнит менеджер).
  - **Lex — НИ ОДНОЙ акции** в разделе (0 из 5 брендов). Решение заказчика (07.07.26):
    Lex включаем пятым брендом, но **без комплектной скидки** — обычные цены, комбо-механики
    нет (`combo_discount_pct = 0`), в PDF/UX скидку на Lex-комплект не обещаем.
  - ⚠️ Страница кампании отдаёт максимум **21 «витринный» товар** (без пагинации/«ещё»).
    Для «весь ассортимент бренда» (`scope=all_brand`) полный состав участников — это все
    товары бренда из каталога по правилам кампании (собрать на Ф4), а не с самой страницы.
- **Ф2. Расчёт итога — ЯДРО СДЕЛАНО.** `matching/combo_pricing.py::compute_combo(items, campaign)`
  → `ComboResult` (подытог, скидка, финал, как ложится: единый % `flat_combo` / рубли на
  наименьший `cascade_cheapest`, флаг `manager_review` для gift/spec_price/unknown, None-кампания
  = Lex без скидки). Валидация: кол-во позиций (по РАЗНЫМ категориям), `requires_oven`, cap на
  верхний тариф. `pdf/cart_style.py` принимает `combo=ComboResult` и ведёт блок «Итого» под все
  механики (легаси `combo_discount_pct`/`promo_note` сохранён). Тесты: `tests/test_combo_pricing.py`
  (12) + новые в `test_cart_style_pdf.py`. Живой E2E совпал с корзиной (Korting 47990+25490 →
  −25% на 25490 → 67 107.50 ₽). Попутно чинён баг: PDF падал на товаре без характеристик.
  ⚠️ Осталось на Ф4/Ф5: вызвать движок из бота — собрать `ComboItem` (цена+категория+is_oven)
  из выбранного комплекта, найти кампании бренда через `PromoStore.campaigns_for_brand`.
- **Ф2.5. Выбор выгоднейшей акции — ЯДРО СДЕЛАНО.** `combo_pricing.best_combo(items, campaigns,
  gift_value)` перебирает ВСЕ акции бренда и берёт с макс. рублёвой выгодой (`discount_total`).
  Акции НЕ суммируются (правила брендов) → одна лучшая. **Подарок оцифровывается** (решение
  заказчика 07.07.26): через хук `gift_value(campaign, items)→(название, цена)` подарок
  становится `applied` с выгодой = цена подарка, но `final_total = subtotal` (подарок СВЕРХУ
  бесплатно, сумму не уменьшает); `pdf/cart_style.py` рисует строку «В подарок: … (стоимость
  Y ₽) — бесплатно» + «Сумма к оплате». Без `gift_value` подарок → «уточнит менеджер».
  Оцифровка подарка — СДЕЛАНА: `promos.parse_gift(rules)→GiftRule` (sum/count пороги→модель),
  хранится `promo_campaigns.gift_json`; `CatalogCache.find_by_model(key)` ищет цену подарка;
  `combo_pricing.make_gift_valuer(lookup)` даёт `gift_value` для `best_combo`. Оцифрованы 2 акции
  (`korting_mbt_v_podarok` сумма 10/25/50 т.р., `midea_posudomoyka_v_podarok` 4 поз.+духовка);
  прочие 5 подарочных (`maunfeld_pmm/novinku`, 3 баннерные без текста) → менеджер. Живая цена
  подарка появится на проде (в локальной БД нет таблицы products). Тесты: 242 всего.
- **Ф3. PDF под эталон — СДЕЛАНА (частично):** `pdf/cart_style.py::build_cart_style_pdf(
  selection, settings, combo_discount_pct, promo_note)` уже рисует шапку/карточки/скидки/
  итого/менеджера/шоурумы; образец совпадает по структуре. Осталось: фото появятся с
  реальными данными; добавить ссылки «Инструкция/Схема»; довести вёрстку по картинке эталона.
  Модель: `CatalogProduct.old_price/discount_pct`. Конфиг: `PDF_HEADER_PHONE/PDF_CITY/
  MANAGER_NAME/EMAIL/PHONE/CITY_PHONE`.
- **Ф4. Движок комплекта — ЯДРО СДЕЛАНО.** `matching/kit_builder.py`:
  `build_brand_kit(brand, specs, candidates_per_spec, campaigns, gift_value)` — по каждой
  позиции берёт лучший товар бренда (`ProductSelector`), считает выгоду через `best_combo`,
  оценивает дизайн-совместимость (`_design_consistency` по цветовой семье — «визуально
  сочетается», честно). `choose_best_kit(...)` перебирает 5 брендов и берёт лучший по
  `rank_key` = покрытие → дизайн → выгода → цена (политика «нет идеального → ближайшее»).
  Lex (нет акций) — валидный бренд, итог по прайсу. Ядро чистое, тесты `test_kit_builder.py`
  (8). Интеграция в `pipeline.py` — СДЕЛАНА: `Pipeline.select_kit(request, level)` собирает

  обогащает выбранные товары (характеристики+фото); `_kit_from_candidates(...)` — чистая
  часть (тесты `test_kit_pipeline.py` без браузера); `build_kit_pdf(kit)` рисует PDF комплекта

  таблицы products → gift-цена/обогащение пустые; логика покрыта тестами на моках).

## Ключевой вопрос (Ф1) — ОТВЕТ ПОЛУЧЕН
**Корзина ekrom НЕ применяет комплектную скидку автоматически.** Живой тест
(логин → добавил в корзину Korting духовой шкаф 45 990 ₽ + варочную панель 25 490 ₽
из акции «Каскадные скидки» → очистил): **ИТОГО = 71 480 ₽ = сумма цен, без скидки**
(каскад −25% на наименьший НЕ применился). Значит «Индивидуальная скидка −X%» в эталонном
PDF ставит МЕНЕДЖЕР вручную. → **% берём из правил кампании (закодированы в датасете Ф1),
не с сайта и не из корзины.** На странице кампании per-товар старой/промо-цены у
комплектных акций тоже НЕТ (проверено: 0 из 21). Подтверждает решение заказчика №3 «итог
считает бот».
