# max-ekrom-bot

Сервис, который по сообщению клиента подбирает встраиваемую технику на
**ekrom.ru**, добавляет товары в корзину и формирует PDF со списком подобранных
позиций для отправки клиенту.

Пример входящего сообщения клиента:

```
Добрый день! Можно подбор средний цен. Сегмент
1. Духовка 600 нерж, не чёрную
2. варочная, 3 конфорки. Электрическая
3. Вытяжка полновстроенная белая
4. СВЧ встроенная в пенале с духовкой
```

На выходе — PDF, который ekrom.ru генерирует из корзины (страница на товар,
блок «Характеристики», цена, блок «Итого» с индивидуальной скидкой и контактами
менеджера).

## Архитектура

Слои изолированы: ядро подбора не зависит от способа ввода и запускается через
Telegram-бот, веб-интерфейс или CLI.

```
Сообщение клиента ──► Парсер (LLM) ──► Поиск ekrom ──► Подбор ──► Корзина ──► PDF ──► Менеджеру
                    CustomerRequest    CatalogProduct  Selection   Playwright
```

| Слой | Где | Назначение |
|------|-----|-----------|
| Интерфейсы | `telegram_app.py`, `webapp.py` | Telegram-бот и веб-интерфейс для менеджеров |
| Парсинг | `parsing/`, `llm/` | Свободный текст → структурированные критерии |
| Сайт | `ekrom/` | Поиск, корзина, скачивание PDF (Playwright + сессия) |
| Подбор | `matching/` | Фильтрация кандидатов + выбор по цене (средний/эконом/премиум) |
| Оркестрация | `pipeline.py`, `cli.py` | Связывает всё вместе |

## Установка

Нужен **Python 3.12**: на 3.13/3.14 закреплённые версии `pydantic-core`, `greenlet`
и `aiohttp` собираются из исходников и требуют компилятор.

```bash
py -3.12 -m venv .venv
# Windows: .venv\Scripts\activate    |   *nix: source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
cp .env.example .env   # затем заполните .env
```

## Конфигурация

Все ключи — в `.env` (см. `.env.example`). Минимум для прототипа:

- `LLM_PROVIDER` — `groq` (по умолчанию в `.env.example`, бесплатный тариф) или
  `openai`. Для `groq` нужен `GROQ_API_KEY`, для `openai` — `OPENAI_API_KEY`.
- `EKROM_BASE_URL` — уже задан; `EKROM_LOGIN`/`EKROM_PASSWORD` — для авто-входа.
- `TELEGRAM_BOT_TOKEN` + `TELEGRAM_ALLOWED_IDS` — для Telegram-бота менеджеров.

Без сети можно парсить и правилами: `LLM_PROVIDER=rule` (см. `parsing/rule_parser.py`),
ключи не требуются. Для РФ-комплаенса LLM-провайдера можно переключить на
YandexGPT/GigaChat — интерфейс уже абстрагирован (`llm/factory.py`), нужно
дописать класс провайдера.

## Авторизация на ekrom.ru

Разведка подтвердила: **капчи в форме входа нет**, поэтому вход можно
автоматизировать. Сессия сохраняется в `data/storage_state.json` и
переиспользуется headless-ботом (в git файл не попадает).

```bash
python scripts/login_ekrom.py
```

- Если в `.env` заданы `EKROM_LOGIN` и `EKROM_PASSWORD` — вход выполнится
  автоматически и сессия сохранится.
- Если учётка не задана — откроется браузер, войдите вручную и нажмите Enter.

Когда сессия протухнет — запустите скрипт снова.

## Запуск

Ядро без мессенджера (отладка):

```bash
python -m max_ekrom_bot.cli parse  "Духовка 600 нерж, не чёрную; варочная 3 конфорки электрическая"
python -m max_ekrom_bot.cli select "Духовка 600 нерж; вытяжка полновстраиваемая белая"
python -m max_ekrom_bot.cli run    "..."  --pdf
```

**Веб-интерфейс для менеджера** (вставил текст клиента → превью → PDF):

```bash
uvicorn max_ekrom_bot.webapp:app --host 127.0.0.1 --port 8000
# открыть http://127.0.0.1:8000 — вставить текст клиента → превью → PDF
```

**Telegram-бот для менеджеров** (работает с локального ПК, отдельный сервер не нужен —
но ПК с ботом должен быть включён):

```bash
# в .env: TELEGRAM_BOT_TOKEN, TELEGRAM_ALLOWED_IDS, GROQ_API_KEY, EKROM_LOGIN/PASSWORD
pip install -r requirements.txt
powershell -File scripts/start_telegram_bot.ps1
# в Telegram: /start → вставить текст клиента → кнопка «Сформировать PDF»
```

Команды бота: `/start`, `/status` (сессия ekrom), `/login` (обновить вход).
Доступ только у user_id из `TELEGRAM_ALLOWED_IDS`.

## Комплекты 5 брендов по акциям (`KIT_MODE=true`)

Основной режим бота: клиент перечисляет позиции («духовка, варочная, вытяжка»), а
бот собирает комплект **из одного бренда** — Korting, Maunfeld, Midea, Lex,
Kuppersberg — и считает выгоду по разделу «Акции» ekrom.

Как это работает:

- **Данные об акциях** собирает `scripts/crawl_promos.py` (раздел `/catalog/aktsii/`):
  бренд, механика, срок, тарифная сетка, исключения, условие подарка → таблицы
  `promo_campaigns`/`promo_items`. Истёкшие акции отсекаются по сроку.
- **Механики** считает `matching/combo_pricing.py`: каскадная скидка на самый
  недорогой товар, плоский % на комплект, холодильник по спеццене, подарок. Корзина
  сайта комплектную скидку не применяет — итог бот считает сам по правилам кампании.
- **Лучшая акция** выбирается перебором всех кампаний бренда по рублёвой выгоде
  (`best_combo`) — акции брендов не суммируются, применяется ровно одна.
- **Комплект** собирает `matching/kit_builder.py`: перебирает 5 брендов и выбирает
  лучший по покрытию → дизайну → выгоде → цене. Lex участвует без комплектной скидки
  (акций у бренда нет) — итог по прайсу.
- **Дизайн-совместимость** — по цветовым группам (тёмная+сталь / светлая+сталь;
  нержавейка и серый нейтральны). Явно заданный клиентом цвет позиции важнее группы.
  Формулировка честная: «визуально сочетается», не «одна линейка» — данных о
  коллекциях на сайте почти нет.
- **PDF** повторяет документ корзины ekrom: основной путь — HTML+CSS → Chromium
  (`pdf/cart_html.py`), фолбэк — reportlab (`pdf/cart_style.py`).

```bash
python scripts/crawl_promos.py     # обновить датасет акций (в cron — 04:40)
```

## Статус

Полный цикл **проверен на реальном сайте** (вход → подбор по категориям с
фильтрами → корзина → скачивание PDF). PDF получается в формате эталона.

Подтверждено и реализовано:

- [x] **Вход без капчи** — автоматизирован (`login()` + `scripts/login_ekrom.py`).
- [x] **URL категорий** — все кухонные под `tekhnika_dlya_kukhni/`.
- [x] **Подбор по характеристикам** — реальные ID фильтров умного фильтра Bitrix
      (цвет, тип духовки, размер 60×60, конфорки, тип варочной) в `ekrom/catalog.py`.
- [x] **Селекторы карточки** — `.product-card` / `data-product-id` / `.product-card__price`.
- [x] **Добавление в корзину** — главная кнопка `button.js-detail-add` (с офферами).
- [x] **Очистка корзины** — «выбрать всё» + «удалить выбранные»; нативный
      `confirm()` Bitrix подтверждается авто-обработчиком диалогов.
- [x] **Выгрузка PDF** — `#print_order_button` из корзины.

Осталось:

- [ ] **Живой прогон режима комплектов на проде** — см. «Следующий шаг» в
      `CONTEXT_HANDOFF.md`.

Про пагинацию: краулер каталога (`crawl_category`) обходит **все** страницы
категории через `?PAGEN_1=N`, поэтому кандидаты из кэша — полные. Первой страницей
(~21 товар) ограничен только живой обход — фолбэк, когда кэш пуст или протух; при
работающем ночном cron этот путь не используется.

## Структура проекта

```
src/max_ekrom_bot/
  config.py            # настройки из .env
  models.py            # доменные модели (запрос, товар, подбор)
  llm/                 # абстракция LLM + провайдеры OpenAI / Groq
  parsing/             # текст клиента → CustomerRequest (LLM или rule_parser)
  ekrom/               # Playwright: каталог, корзина, PDF, сессия
  matching/            # подбор по цене (средний/эконом/премиум)
  messenger/           # форматирование ответов для Telegram
  pipeline.py          # оркестрация ядра
  cli.py               # запуск из командной строки
  webapp.py            # веб-интерфейс для менеджера (FastAPI)
  telegram_app.py      # Telegram-бот для менеджеров (long polling)
scripts/login_ekrom.py # разовая ручная авторизация → storage_state.json
tests/                 # юнит-тесты чистой логики (pytest, без сети)
```
