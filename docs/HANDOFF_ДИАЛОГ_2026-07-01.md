## Кратко: что это

Telegram-бот подбора бытовой техники **ekrom.ru**. Клиент пишет запрос → бот
подбирает по каталогу → присылает **свой PDF** с ценами, фото и характеристиками.
Прод на VPS, репозиторий: https://github.com/grisha520/ekrom_tg_bot

**Бот в Telegram:** `@ekroom_bot`

## Что сделано в ЭТОМ диалоге

### 1. E2E-тестирование пайплайна

- Скрипт: `scripts/client_e2e_suite.py` — 12 кейсов (parse → select → enrich → PDF).
- Локальный прогон: **12/12 OK** (~262 с без кэша каталога, Groq в локальном `.env`).
- HTML-отчёт: `data/out/e2e_client_report.html`
- На проде категории проверены ранее (резолвер Pro + только родители):
  винный шкаф → Meyvel, морозилка → Midea, кофемашина → Jacky's, утюг → Laurastar.

**Замечания e2e (качество подбора, не категорий):**
- «морозильная камера» иногда даёт **ларь** вместо камеры.
- «кофемашина автоматическая» иногда **кофеварка**, не автомат Jacky's.

### 2. Клиентский UX (`187b9a6`)

Модуль: `src/max_ekrom_bot/messenger/client_ux.py`

- Приветствие `/start` с примерами и ссылкой на сайт.
- Клавиатура: **💡 Примеры** · **ℹ️ Как пользоваться** · **📞 Контакты**.
- Inline-примеры: духовка, посудомойка+вытяжка, холодильник.
- Пошаговый статус: разбор → подбор → PDF.
- Мягкий ответ на «привет» (без LLM-подбора).
- Клиентское превью + дисклеймер про менеджера.
- Кнопки после PDF: сайт, звонок, ещё примеры.

### 3. История PDF «📂 Мои подборы» (`79c9757`)

- `src/max_ekrom_bot/pick_history.py` — SQLite + файлы `data/history/{user_id}/`.
- Кнопка **📂 Мои подборы**, команда `/history`.
- До **20** подборов на пользователя, хранение **30 дней**.
- Inline-кнопки → повторная отправка того же PDF без нового подбора.

### 4. Статистика для админа (`79c9757`)

- `src/max_ekrom_bot/bot_metrics.py` — метрики в `data/bot_analytics.db`.
- Кнопка **📊 Статистика**, команда `/stats` (только `TELEGRAM_ADMIN_IDS`).
- Показывает за сегодня (МСК): запросы, уникальные клиенты, часовой поток,
  среднее время подбора, p95, **макс. ожидание в очереди**, успех/ошибки.

## Архитектура (напоминание)

```
Клиент → telegram_app.py
  → parse (YandexGPT Lite)
  → category_resolver (Pro, только родительские категории)
  → кандидаты из catalog.db (USE_CATALOG_CACHE=true)
  → selector.py (детерминированный)
  → enrich_chosen (Playwright, _EKROM_LOCK — один подбор за раз)
  → build_offer_pdf (reportlab)
  → история + метрики + лид админу
```

### Ключевые файлы

| Файл | Назначение |
|------|------------|
| `telegram_app.py` | Бот, роли, клиент/оператор, история, stats |
| `messenger/client_ux.py` | Тексты и кнопки клиента |
| `pick_history.py` | История PDF |
| `bot_metrics.py` | Метрики для админа |
| `pipeline.py` | Ядро подбора |
| `matching/selector.py` | Фильтры и скоринг |
| `parsing/category_resolver.py` | Выбор категории (Pro) |
| `pdf/offer.py` | Клиентский PDF v2 |
| `ekrom/catalog_cache.py` | SQLite-кэш каталога (WAL) |
| `scripts/client_e2e_suite.py` | E2E-прогон кейсов |

Локальный `.env` на ПК пользователя **устарел** (Groq, не Yandex) — для точного e2e
нужен прогон на сервере или синхронизация `.env`.

## Мощности VPS — хватит ли на поток

**PARs-2 (2 CPU / 4 ГБ / 60 ГБ)** — достаточно для старта и первых месяцев:

| Сценарий | Оценка |
|----------|--------|
| Комфортно | 30–80 клиентов/день, пики 5–10 одновременных |
| С очередью | 100–200/день (ожидание 1–3 мин в пике) |
| Узкое место | `_EKROM_LOCK` — подборы строго по очереди |
| Диск под историю PDF | с лимитами 20×30 дней — запас большой |
